# 基于T80的搬运流水、编码优化与32 PE低功耗实施计划

文档日期：2026-11-15（北京时间）  
文档状态：实施计划；本文中的性能预算、修改方案不代表已完成实现或验证。

## 1. 目标、基线与固定约束

本轮最终交付固定为 **16列×2行、32 PE脉动阵列**，依次完成：

**分块综合基线 → 搬运流水 → 完整编码流 → 32 PE及缓存适配 → 正式时钟门控。**

已确认的优先级：

1. 正确性、规定的数据路径和150 MHz时序必须满足。
2. 项目计入面积 **≤1.00 mm²**。
3. 在上述条件下优先提高完整任务吞吐，目标方向为接近 **3000 task/s**。
4. MAC缩减阶段争取面积 **<0.50 mm²**，作为努力目标；不为此优先牺牲吞吐。
5. 同等吞吐下，优先选择整机单任务能耗更低的版本。

本次核对的分支头仍为 `575b3cbdf9f2cef92f7cf90acd3b2168ba21fdd4`，T80受测硬件为 `876b883d95199f2d1889019cbfec4c93c42d1be5`。实施前再次检查更新，在独立个人分支开发，保留T80及全部历史证据。

固定不变：

- 150 MHz、原32位ICB、原平台总线缓冲参数、分路器在途数及规定的存储时序。
- 源读→共享写成功ACK→原总线读回→解码→计算→完整输出写回。
- 不通过写数据或写ACK旁路解码器，不新增共享SRAM直连端口。
- X14/F10、W12/F12、乘积26/F22、累加器及偏置32/F22、total33/F22、result16/F12，SHIFT=10。
- 保持半值远离零舍入、饱和规则和完整99×256输出矩阵，不压缩输出。
- 任务冷启动，不跨任务预装载；使用真实E203配置、IRQ/WFI及异常处理。

**目标边界：**32 PE在150 MHz下纯算术峰值约2959 task/s；两行分块计入最后单行尾块后，理想计算上限约2930 task/s。3000作为逼近方向，不作为可以保证达到的验收值。

## 2. 分阶段修改与冻结

| 阶段版本 | 核心改动 | 必须保留的对照 |
|---|---|---|
| S0：T80分块综合基线 | 建立三个综合块、顶层链接和统一报告 | 原T80整体综合与已有功能证据 |
| S1：P80 | 请求流水、响应队列、信用管理 | 相同80 PE、相同编码、无新增门控 |
| S2：C80 | 完整编码流优化与匹配解码器 | 相同80 PE和S1搬运结构 |
| S3：C32 | 改为32 PE，适配调度、结果及缓存 | S2相同输入编码文件和外部传输规则 |
| S4：G32 | 在稳定C32基础上加入正式门控 | 同源码配置的门控旁路版本 |

每个阶段完成自身功能、性能、面积、时序及功耗报告后冻结。探索中间结果可以保存，但不继承前一版本PASS，也不自动晋级为正式版本。

### S0：先建立分块综合和面积归属基线

划分如下：

- **CPU/SoC块**：E203、原有TCM、原平台互连及固定控制逻辑。
- **共享SRAM块**：512 KiB共享SRAM控制器和真实宏引用。
- **加速器块**：DMA、解码器、内部缓存、MAC、结果通路及团队新增接口逻辑。

新增仲裁、译码和IRQ胶合逻辑必须逐项明确归属。**综合层次与赛题面积归属分别记录**，不能因为逻辑位于CPU块就免计新增面积。

三个块分别生成DDC，再顶层链接并检查跨块时序。统一工艺角、库、时钟、负载和接口预算，不能让每个块分别独占完整6.667 ns预算。

同时输出：

- 按实例归属审计的项目面积；
- 与旧T80口径一致的保守面积上界；
- CPU/SoC、共享SRAM、加速器及整机面积。

若两种面积口径有差异，解释差额来源，不通过更换统计口径宣称硬件面积下降。面积归属未审清前，按保守上界判断1.00 mm²门槛。

DDC复用以源码、参数、库、约束和工具版本指纹为依据；相关依赖变化即重综合。记录实际综合时间，不预先承诺分块一定更快。

### S1：利用原总线已有缓冲，提高连续请求能力

修改团队新增仲裁器与DMA的单笔待响应管理，采用**有序事务信息队列**；不修改原总线并发参数。

实施规则：

- 请求只在 `valid && ready` 时进入“已接受事务队列”，响应只在响应握手时出队。
- 仲裁队列记录CPU/DMA归属；DMA队列记录事务类型、地址或序号及错误归属。
- 支持同拍出队与入队；反压期间请求及响应内容保持稳定。
- 信用覆盖已预约、已接受未返回、已返回未消费的数据，避免响应到达后才发现无空间。
- 共享读只对已经收到成功写ACK的地址发布；失败写不得释放读依赖。
- CPU公平性按已接受请求轮转；DMA内部保留输出高水位保护、读回依赖和源信用约束。
- 错误或软取消后停止安排新工作；已拉高且受反压的请求遵守协议，已接受事务全部排空，旧任务返回不得进入新任务。
- DONE要求所有输出成功写回，相关请求、响应和缓存状态均已排空。

仅对**新增事务信息队列**评估深度2、4、8；原数据FIFO容量和源信用先保持T80不变。选择满足正确性、面积门槛且吞吐距最佳结果不超过1%的最小队列配置。

先测原总线的持续接受间隔、响应间隔和占用率。若新增队列没有提升原接口利用率，记录原因，不通过修改原平台参数强行获得收益。

### S2：先软件筛选，再修改编码与解码器

使用既有20条语音×12层的同一整数数据，比较：

- 现有编码；
- X行内邻近预测、前一行预测及精确残差位打包；
- 有界Rice编码，带长残差逃逸和原始块回退；
- 偏置32位紧凑打包；
- 减少块头、模式表和对齐填充。

筛选统计必须包括完整任务所有字节：X、W、偏置、格式头、块头、填充及回退。偏置从三个半字改成两个，净载荷每任务减少512字节；完整文件净收益仍以实测为准。

解码设计要求：

- 使用足够宽的整数中间值，禁止截断或饱和残差。
- 每块有明确边界和可恢复的预测初始状态；依赖前一行的模式必须计入参考行缓存和等待成本。
- 格式按逻辑矩阵行、列和权重tile定义，不绑定“五行MAC批次”，使80 PE与32 PE使用同一编码文件。
- 保留原始块回退和确定性的模式选择规则，限制最坏解码时间。
- 输出逻辑数据顺序与原数学模型一致；紧凑偏置如需兼容旧内部加载器，可在解码端恢复内部表示，但不得增加外部重复传输。

先验证逐整数往返，再测解码周期、首块可用时间、持续供数和缓存冲突。只有完整任务周期改善、面积满足约束的格式才进入C80；压缩率改善但实际更慢的候选不采用。

### S3：改为16×2，逐步处理面积目标

先冻结C80，再建立C32：

- 80 PE改为32 PE，配套缩减偏斜链、累加器、结果暂存和转换通路。
- 调度改为50个行组、16个列tile；最后行组仅第一行有效。
- 禁止最后无效行发出存储访问或结果写回。
- 调整块标签宽度、计数器、结果坐标、缓存选择及流水排空条件。
- 保持C80编码文件、完整输出位置、外部事务语义及数值参考一致。

**分两步冻结，避免把面积变化混在一起：**

1. **C32-A：**先保留完整X缓存容量，适配两行取数，单独测量缩减阵列及结果通路的收益。
2. **C32-B：**再评估更紧凑的X缓存组织。候选采用两个4096×16单端口宏，按行奇偶分bank，地址为 `floor(row/2)×64+k`；保留完整X，权重物理双缓冲不变。

C32-B必须处理加载与计算的单端口冲突；同bank冲突时优先计算读取，加载通过反压等待。不能为了减少宏数省略真实读写，或假设编码器可以无条件每拍写入多个同bank数据。

C32-B只有在满足1.00 mm²门槛且完整吞吐不低于C32-A时才优先采用；吞吐相同再比较面积和能耗。若0.50 mm²未达到，报告MAC、缓存、DMA、解码和接口逻辑的面积分解，最终仍交付32 PE，不自动恢复80 PE。

### S4：稳定结构后加入正式门控

优先门控MAC、偏斜数据、偏置、结果寄存器以及FIFO数据存储；控制、valid、信用、响应接收、IRQ和取消逻辑保持可运行。

- 使用实际工艺ICG及明确的测试使能。
- 共享SRAM先使用宏片选/使能；本轮默认不额外门控其时钟，除非真实宏要求和验证证据齐备。
- CPU沿用平台已有WFI及唤醒机制，不新增未经验证的CPU总时钟门控。
- 门控版和静态旁路版应具有相同的任务输出、协议行为和完整周期。
- 验证门控setup/hold、复位、停顿后恢复、异常排空和IRQ唤醒。

最终G32应比同配置C32降低整机单任务能耗；未产生收益的门控域关闭，不将“插入了ICG”当作节能验收。

## 3. 接口、版本与吞吐预算

MMIO地址和现有命令语义保持兼容；各冻结版本使用独立硬件身份。数值身份保持不变，编码格式及阵列布局变化使用新的格式/布局身份，软件必须检查匹配，禁止静默误解码。

旧T80编码及软件参考保留为独立回归入口。正式新网表无需同时容纳所有历史解码器，避免兼容逻辑无谓增加面积。

新增或完善以下性能计数：

- 四类事务的请求、接受、响应和成功数量；
- 各队列峰值占用、信用阻塞和响应反压；
- 共享写ACK依赖等待；
- 解码有效周期、首块前缀、供数空拍；
- MAC有效更新、尾块损失、结果反压及最终排空。

对于完整编码流B字节，保留：

```text
N_DMA = 3 × (B / 4) + 12672
```

如果S1实测证明持续服务率达到此前条件预算，则：

```text
C_bus ≈ 1.75 × B + 25344
```

32 PE两行分块的计算下界为：

```text
C_MAC ≥ ceil(99 / 2) × (256 / 16) × 64 = 51200
```

完整周期至少受二者较大值限制，还要计入未被重叠的启动、解码、流水和排空时间。

| 完整编码流 | 搬运条件上限 | 32 PE综合理想上限 |
|---|---:|---:|
| 当前29,756 B | 约1938 task/s | 不高于1938 task/s |
| 20 KiB | 约2452 task/s | 不高于2452 task/s |
| 16 KiB | 约2777 task/s | 不高于2777 task/s |
| 12 KiB | 约3202 task/s | 不高于2930 task/s |

上述均为预算，不是承诺。按该模型，编码流需要降至约 **14.4 KiB或更低**，搬运预算才可能不高于51200拍；是否能达到以及是否连续供数，由S1/S2证据决定。

## 4. 验证、冻结与交付标准

每个改变硬件的冻结版本完成以下验证：

- 同一前20条语音×12层，共240任务、6,082,560个输出，逐项检查坐标、`total/result/saturated`及完整共享SRAM输出。
- 同批浮点参考逐层汇总NRMSE；保持数值不变的版本必须与T80整数结果完全一致，不能仅以NRMSE达标替代逐位核对。
- 原14例组件/矩阵回归，以及至少10,000随机计算块和对应定向边界测试。
- 随机源等待、输出反压、CPU竞争、队列满空转换、同拍进出、四类事务错误、软取消、多笔排空、连续任务及复位。
- SRAM一拍正式配置、两拍延迟适应性测试；厂商模型与本地替代模型结果分别标记。
- 每个新最终网表进行自身功能门级14例、固定12任务完整活动采集和功耗分析。无SDF门级明确标注，不宣称物理签核。

固定12任务报告完整周期与功耗；240任务另报平均、最坏任务及正确性，不能混用两组平均值。整机功耗从同一最终网表、同一任务窗口汇总，不能拼接不同版本的块功耗。

每版交付JSON、CSV和中文摘要，至少记录：

- 源码、固件、数据、库、约束、网表及运行包哈希；
- 功能、精度、吞吐、面积、时序、平均功耗和µJ/task；
- 相对前一阶段及原T80的变化；
- 已通过、失败、未测与模型限制。

既有T80结果用于基线引用；分块综合产生的新网表须自行验证。服务器运行使用独立目录，先核对进程、锁和空间，不覆盖历史包、不自动恢复旧队列。

本轮只使用约定的20条语音进行正式批量验证。最终G32稳定后，再申请是否运行完整100条；官方600条、布局后时序功耗及物理签核均不纳入已通过结论。
