# C80编码协议准备

状态：主机软件实现和同批240任务往返通过；未冻结，未实现C80 RTL。只有P80独立验收并持久归档后，才开始对应解码硬件。本文对应`c80_codec.py`及`c80_codec_candidate.py`，不修改原P80格式。

## 全局身份与顺序

全流以小端32位字传输。头为8个32位字：MAGIC `0x3543574b`、VERSION `0x00050000`、LAYOUT `0x00100006`、raw标志、完整字节数、23232、46464、NUMERIC `0x000e0c20`。仅raw标志0/1合法；完整长度须4字节对齐、不大于46496，raw模式须恰为46496。

载荷为W0/b0、X的99个逻辑行、W1/b1至W15/b15。每个W tile有1024个signed12元素，按k从0至63、lane从0至15；随后16个小端signed32偏置。X按row、k排列。预测每8个逻辑行重置，与5行或2行PE分块无关。

所有压缩块从字节边界开始。字段内部按低位先行连接到位流，块末未用高位填0；整流末尾最多3个零字节。不得将块按32位重新对齐，否则改变字节数与既有筛选输入。

raw整流没有块描述符、位宽表或预测元信息：W/X使用符号扩展到16位的容器，偏置仍为32位。raw路径须检查W高4位和X高2位，不静默截断。

## 块描述符

每个压缩X行或W tile以小端16位描述符开始：bit3:0为mode，bit7:4为parameter，bit15:8必须为0。下表的零位宽表示全零字段，不消耗载荷位。

| X mode | parameter | 描述符后的内容 |
|---|---|---|
| 0 raw14 | 必须14 | 64个signed14 |
| 1 signed | 0～14 | 64个指定位宽补码 |
| 2 delta | 0～14 | signed16基值，然后64个无符号差值 |
| 3 adjacent_fixed | 0～15 | signed16首值，然后63个有符号残差 |
| 4 previous_fixed | 0～15 | 相对前一逻辑行的64个有符号残差 |
| 5 adjacent_rice | 0～11 | signed16首值，然后63个有界Rice残差 |
| 6 previous_rice | 0～11 | 相对前一逻辑行的64个有界Rice残差 |

基值/首值必须属于signed14范围；每次重建用足够宽有符号加法，重建后检查signed14范围。每8行组的首行不能使用mode4/6；前行参考保存在独立64×14状态，不能访问计算中的单端口X宏获取参考。

| W mode | parameter | 描述符后的内容 |
|---|---|---|
| 0 raw12 | 必须12 | 1024个signed12 |
| 1 column | 必须0 | 16个4位列位宽，再按k→lane存1024个补码 |
| 2 block64 | 必须0 | 16个4位块位宽，再按原顺序存1024个补码 |
| 3 rice | 0～11 | 1024个有界Rice值 |
| 4 column_rice | 必须0 | 16个4位Rice参数，再按k→lane存1024个值 |

位宽表项允许0～12；Rice表项允许0～11。表共64位，按lane或块索引从低半字节开始。block64中的块索引为`floor(i/64)`，不是列索引；列模式索引为`i%16`。

## 有界Rice

有符号v的zigzag为非负值`2*v`或负值`-2*v-1`。参数k给出商`u>>k`和低k位余数。商小于15时，位流为连续q个1、一个0、k位余数；商达到15时，15个连续1后直接放完整补码逃逸值，不另放终止0或余数。

X残差逃逸为signed15，W逃逸为signed12；符号最长分别30和27位。非逃逸zigzag恢复后也检查范围，不能因逃逸位宽受限而忽略非逃逸的大值。W重建必须在[-2048,2047]内；X最终值必须在[-8192,8191]内。

软件确定性等长优先序：X为signed、raw14、delta、adjacent_fixed、adjacent_rice、previous_fixed、previous_rice；W为column、raw12、block64、rice、column_rice。Rice参数按成本最小、再k最小。完整压缩body填充后大于等于46464字节时采用整流raw，避免负收益。

## 内部装载与协议约束

外部规范流23232半字；内部既有加载器仍需23488半字。偏置每次从外部读取低16和高16，内部额外恢复`0000`或`00ff`第三半字。内部恢复不增加源读取、共享写入或共享读回事务。

准备采用128位reservoir、每次最多一个数值/元信息动作。输入为原32位共享读回响应；仅共享写成功ACK后才允许原总线读回，不以ACK数据旁路。输出保持现有64位接口，但首版out_count=1；其余位清零。新输入本拍进入，后续拍才参与解析。

输出反压时数值、计数及valid保持，预测状态、元素位置和消费位数只在实际交接后推进。预测首值、字节填充等非输出元信息独立消费，不能重复生成结果。偏置第三半字仅在内部交接，不能重复消耗输入位。取消清理预测有效性、reservoir和输出待处理状态，DMA独立负责排空已接受事务。

必须检查：完整头身份、长度、全部表项、段/元素计数、每块及整流零填充、截断、raw符号扩展、重建溢出、额外尾字节。解码完成仅表示输入完整恢复，不代表整任务DONE；DONE仍等全部结果成功写ACK及事务排空。
