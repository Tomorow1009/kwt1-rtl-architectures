# 基于N1：先改搬运与MAC，结构冻结后再加入时钟门控

## 1. 基线与实施顺序

以N1已受测硬件 **`9305c6948c764fed01fe86b20bb3db94170299ab`** 为计算和数值基线。最新分支中的工具可经核对后复用，**不直接以N2门控RTL作为起点**。

| 阶段 | 搬运路径 | MAC | 新增正式时钟门控 |
|---|---|---|---|
| N1历史基线 | 共享写ACK后转发 | 5×16，80 PE | 无 |
| T80搬运版 | 共享写入后，经原总线真实读回 | 5×16，80 PE | 无 |
| T64结构版 | 与T80相同 | 4×16，64 PE | 无 |
| G64门控版 | 与T64完全相同 | 4×16，64 PE | 有 |

分别冻结T80、T64、G64，取得各自精度、吞吐、面积和功耗数据。这样：

- N1→T80观察搬运路径及必要总线接入修改的影响。
- T80→T64观察PE数量和配套取数调度的影响。
- T64→G64观察正式时钟门控的影响。

原平台已有门控保持不变；前两阶段不新增加速器ICG。

## 2. 先完成搬运与64 PE结构

### T80：真实共享SRAM读回

数据流固定为：

```text
编码源 → 原32位接口读取 → DMA
→ 原System Bus写入共享SRAM输入区
→ 对应地址写成功
→ 原System Bus读取共享SRAM
→ DMA读响应FIFO → 解码与精确重建
→ X缓存 / 权重双缓冲 → 80 PE
→ 舍入饱和 / 输出FIFO
→ 原System Bus写回完整输出矩阵
→ 最终成功写ACK、事务排空 → DONE / IRQ
```

- 核对官方平台与安装补丁，确保四类事务均经过原System Bus。默认采用原`mem_fab`上游CPU/DMA仲裁，保持原位宽、FIFO和并发限制。
- 删除写数据直接供给解码器的路径。解码器只能消费共享SRAM读响应。
- 按地址追踪成功写入和读回进度，允许读取已写成功的前缀；不跨任务预装载。
- 保留错误、取消、反压、CPU公平访问和事务排空机制。
- 保留当前编码格式、缓存容量和权重双缓冲，本阶段不加入新压缩算法。

### T64：缩为4×16脉动阵列

在冻结T80基础上，只修改计算配置及必要配套逻辑：

- 保持脉动架构，80 PE改为64 PE。
- 99行分25组，最后一组只有3行有效。
- 修改取数映射、波前标签、结果槽和尾块屏蔽；正确处理四行窗口跨原五行缓存分组。
- 保持与T80相同的编码、总线、物理缓存容量、FIFO容量和搬运策略。

两版均保持：

- X14/F10、W12/F12、acc及bias32/F22、total33/F22、result16/F12，`SHIFT=10`。
- 原舍入和饱和规则。
- 完整99×256输出，共50,688字节；两个16位结果打包为32位写入，不压缩输出。
- 150 MHz及项目面积≤1.20 mm²的现有较严门槛。

## 3. 结构稳定后加入正式门控

T64完成以下项目后，才认定结构稳定并进入G64：

- 数值与协议压力测试通过。
- 真实E203上的固定20条语音全部通过。
- 同网表功能门级检查通过。
- 面积、时序、完整吞吐及系统功耗报告齐全。
- 无未关闭的正确性、死锁或事务丢失问题。

G64只加入工艺ICG及必要使能逻辑，不同时调整编码、FIFO、MAC调度或缓存组织。

- 门控对象为PE及相关数据寄存器、偏置、结果和FIFO数据存储寄存器。
- 控制、valid、标签、总线响应、取消及IRQ保持运行。
- 有未完成波前、结果发布或排空工作时，不得错误停钟。
- SRAM沿用合法片选及写使能控制。
- 使用真实工艺ICG；不以普通组合逻辑生成时钟。
- 门控与静态旁路模式逐周期比较，要求功能、握手、DONE/IRQ和完整周期一致。

G64必须取得自己的综合、门级、活动和功耗证据。若门控导致时序失败、功能异常或能耗恶化，保留失败记录并以T64作为候选。

## 4. 吞吐预算与逐版验证

当前N1固定12任务平均编码输入为29,756字节。真实读回后：

- **纯流量乐观上限：约4287 task/s**，假设所有事务每拍一笔。
- 若服务器保持已检查的原总线控制，且共享同步读取存在至少两拍发起间隔，其他事务取最乐观条件，则上限收紧至 **约3535 task/s**。
- 实际仲裁、响应延迟、解码和排空可能进一步降低吞吐。
- 64 PE规则分块的纯计算上限约 **5859 task/s**，因此当前编码量下仍优先受搬运限制。
- 正式门控的目标是降低功耗和能耗，预期不改变任务周期，不将其作为吞吐提升手段。

每个新版本执行：

1. 至少10,000随机计算块及数值、尾块、跨bank、1/2拍SRAM、反压、错误、取消和连续任务检查。
2. 固定采用现有100条清单的前20条，全部12层，共 **240任务、6,082,560个输出**，逐项比较`total/result/saturated`。
3. 对同批完整浮点参考按层汇总计算NRMSE，不平均样本百分比。
4. 使用相同固定12性能任务、工艺角、约束和完整计时窗口，报告吞吐、项目/整机面积、动态/静态功耗及µJ/task。
5. 冻结源码、固件、数据、网表、活动文件哈希和运行目录；缺项标记“未验证”，不借用旧版PASS。
