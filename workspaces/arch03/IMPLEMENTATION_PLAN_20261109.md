## 一、核查结论

已回读项目对话中的赛题来源，并逐页核对本地 **15 张正式赛题图片（封面及正文 14 页）**，同时复查组委会关于参数加载、计时和工艺角的答复。

**上一版方向正确，但有遗漏和过度安排。下面的修订版能够覆盖本科必做任务及后续决赛交付；一周内能否全部验收通过，仍取决于整机工艺适配、时序和功耗流程的实际结果，不能提前保证。**

必须修正的地方：

| 事项 | 正式要求及计划修订 |
|---|---|
| 官方评测数据 | 600 条样本清单在**评测结束后公布**，不另发校准集、验证集或预处理包。删除“等待官方数据到位”的前置条件，工具必须处理未见过的合法输入。 |
| 验证规模 | 600 样本用于软件数值模型评估；RTL 对照为覆盖 12 层的 12 个性能任务及独立组件向量。旧 1,200 组 CPU 回归属于内部加严，不作为本周交付前置。 |
| 连续任务 | 必须验证连续任务及参数切换，但没有规定“12 层数据同时驻留、一次 CPU 启动全部执行”。先完成全部层独立测试及不同层连续测试，避免复杂供数方案阻塞验收。 |
| 数值接口 | 除模型和参数转换脚本，还需完整的**编码、解码及格式说明**；全部解码结果必须有限。 |
| 初赛交付 | 本科任务 1—3 的工程及数值材料必须齐全；任务 3 已包含综合网表、约束、面积与功耗估算、周期和吞吐记录，不能全部推迟到决赛。 |
| 面积范围 | 官方计分范围与整系统面积分别列账。当前团队补齐的 512 KiB 共享 SRAM 是否属于规定的复用存储，需要依据平台实现确认，不能直接按新增或豁免下结论。 |
| 来源与独立性 | 补充全部设计来源、引用和自主设计说明；参考答案只用于验证，不得进入实际计算路径或替代硬件运算。 |
| 提交形式 | 核查实际提交系统的模板、文件字段和视频要求；不能依据群友“只交报告”的说法删减工程。 |

## 二、基线与范围

保留当前 8 路、16 位输入／权重、Q12 数值基线。已有真实 E203 的 14 组矩阵验收记录；本次复算的单样本最差层 NRMSE 为 **0.141052%**。这些可以作为起点，但不能替代多样本精度、整机综合和系统能耗验收。

GitHub 队友的 [PR #6](https://github.com/Tomorow1009/kwt1-rtl-architectures/pull/6) 已实现坐标递推及被动计数，直接作为待测优化候选，不重复开发，也不把静态检查当成实测收益。

固定以下边界：

- 使用指定模型提交 `237e4097`、KWT-1 `best_weights`，关闭训练、随机增强和 Dropout；不训练、微调、蒸馏或改变模型基本结构。
- 硬件完成长度 64 点积、偏置和数值转换，以及 `99×64 × 64×256 → 99×256` 的完整计算与写回，支持 12 层参数。
- 各层输入独立从指定浮点模型提取；不能把上一层 FC1 的 `99×256` 输出直接作为下一层输入。
- 使用官方 E203 平台和一种合法接入方式，继续采用当前 System Bus／ICB 路线。保持规定的 512 KiB 共享存储，不增加 DDR 或其他外部存储控制器。
- 本周不开展注意力、GELU、第二线性层、完整 Transformer、布局布线或流片工作；它们不是本科必做验收的前置条件。
- 本计划由主代理协调数值、RTL／固件、EDA 三条准备工作；共享服务器统一调度。旧暂停运行保留，新增验证使用独立提交和运行目录。

## 三、实现与验收任务

### 1. 完成必做功能和通用输入接口

保留 `kwt_run_layer` 与现有 MMIO 协议，补齐通用数据转换和结果导出入口：

- 输入任意合法的层号及完整 `X/W/b`，生成硬件数据和数值配置。
- 软件整数模型严格复现 RTL 的符号、位宽、累加、偏置对齐、舍入和饱和。
- 解码实际硬件输出为实数，输出逐任务结果、误差和状态；不依赖预先保存的某个样本答案。
- 文档明确矩阵顺序、字节序、各数据位宽与尺度、SRAM 布局、寄存器、启动和完成语义。

功能验收覆盖：

- 全部 12 层真实参数，每任务核对全部 25,344 个结果。
- 零值、正负极值、抵消、舍入半值、饱和边界和支持的 shift 边界。
- 不同层及不同输入的连续任务、任务中止、复位恢复。
- 总线等待、输出反压、错误地址、写掩码、重复启动及超时恢复。
- 冷任务开始时清空或失效缓存，证明不会读取上一任务的有效数据。

12 层一次启动完整序列保留为增强回归，不要求同时缓存全部层参数。测试平台可以提供合法加载激励，但必须通过实际平台访问路径，计入传输时间；不得直接修改目标存储来跳过传输或代算。

### 2. 建立符合规则的数值评估

新增完整矩阵导出模式，一次浮点前向捕获全部 12 层，不从现有 `Y[0,0]` 档案推测其余坐标。

- 固定 600 条开发评估样本及清单，覆盖目标词、其他语音和按指定流程生成的静音；它是内部验证集，不冒称官方评测集。
- 校准只使用训练划分；验证划分用于调试，测试划分不参与数值配置调整。
- 软件模型评估全部 `600×12` 个完整任务；RTL／CPU 首先覆盖 12 层及组件向量，再增加软件筛出的最差误差、最大幅值任务。
- NRMSE 使用参考输出 RMS 归一化，分母下限为 `1e-8`。按层累计全部样本后取最大值，同时单独报告每个任务误差。
- 官方硬门槛：最差层汇总 **≤3%**，每个参评性能任务也分别 **≤3%**；全部解码结果有限，RTL 与整数模型逐位一致。
- 内部目标仍为最差层 **≤0.6%**，争取 **≤0.3%**。先评估现有 Q12，只有证据显示必要时才做每层尺度调整。

评估器需要加入缺失／重复输出、非有限值、错误尺度，以及“层汇总通过但某性能任务失败”的反例测试。

### 3. 完成整机综合、时序和面积核算

- 核对并补齐 TCM、ROM、时钟及复位的工艺实现，验证容量、读延迟、写掩码和地址范围；功能仿真分支不能替代 ASIC 实现。
- 默认沿用现有 **SS、0.99 V、125°C** 条件，锁定标准单元和 SRAM 库。
- 使用准确的 **150 MHz** 时钟约束，周期不大于 `6.666666667 ns`；检查 setup／hold、未约束路径及异常路径依据。
- 现有 `6.667 ns` 报告的极小余量不沿用为严格 150 MHz 通过证据；修复后重新验收。
- 输出整系统面积与官方计分面积两份明细。标准单元与 SRAM 分开核算，采用指定面积依据，避免遗漏和重复。
- 完成综合前后功能一致性验证，覆盖 12 层和必要边界／控制测试；可用等价检查辅助，SDF 用于需要的时序验证。
- 不把多角物理签核、版图边长或布局布线增加为本周必过条件。

### 4. 完成规范性能与系统功耗测量

本科一个 task 固定为一次 FC1 计算及全部结果写回。

- 计时从输入和参数开始装载，到最后结果成功写回结束；包含真实传输、总线等待、E203 调度和计算。
- 明确任务外测试源准备、任务缓存清空、实际装载三者边界；不能用核心 START/DONE 代替全流程窗口。
- 使用同窗口 VCD／SAIF，统计 E203、加速器、互连和 SRAM 的动态与静态功耗。
- 报告活动映射覆盖、未标注对象和 SRAM 功耗依据；未建模部分不能按零功耗处理。
- 同时记录参数加载开销、SRAM 访问量及等待，用于解释瓶颈。
- 吞吐、能耗、面积和精度绑定同一冻结配置；不同版本的最好结果不能拼接。

## 五、优化、交付与最终判定

本周的两项软件改进只作为低风险候选：

1. 复用 PR #6 的坐标递推，保留逐输出校验。
2. 对齐的输入源复制采用 32 位访问，保留字节顺序和 fence；加速器 LOAD 仍遵循原就绪协议。

分别测基线、单项改进及组合，记录周期、能耗、面积、误差和负收益。后续再按瓶颈选择自主搬运、双缓冲／流水和并行度调整，形成两到三个有充分量化证据的创新方向。数百 task/s 和 500 以上仍是内部优化目标，不作为本科达标条件或一周承诺。

最终交付必须包含：

- RTL、驱动、测试平台、软件数值模型、编码／解码和参数转换脚本。
- 数值格式、模型和数据来源、工具版本、配置及文件哈希。
- 综合网表、SDC、功能／时序／面积／功耗报告，周期和吞吐记录。
- 决赛所需的 SAIF／VCD、能耗记录、创新对照、答辩材料。
- E203、模型、SRAM、基础实现和团队修改的来源／引用／自主贡献说明。
- 可复现运行入口、通过／失败／未验证清单；测试参考答案与实际运行路径明确隔离。

**计划完成的判据是上述证据真实齐全，而不是代码写完或仿真出现一次 PASS。** 当前工程具备继续完成本科要求的基础；最大风险仍是整机工艺适配、严格时序和系统功耗闭环，应优先解决这三项。
