# 压缩32位ICB候选ABI v2

新模块独立于原dma16。控制基址40000000，源B0000000..B000BFFF，共享A0000000..A007FFFF，默认输出A000C000；地址4字节对齐，源/输入/输出不重叠。源长度为32..47008且4字节对齐，输出固定50688B。芯片侧完整计时包含所有源请求、共享写入、等待、解码、计算、输出写响应和排空。

布局00100002使用[codec v2](ICB32_CODEC_V2.md)。原00100001在DMA模式明确拒绝；原独立DMA16仍支持它。debug模式保留旧单半字LOAD/单结果OUTPUT地址及数值规则，接受00100001/00100002；debug不能将压缩字节当半字直接灌入。新正式驱动只支持任务DMA。

原DMA16_ABI.md的00..70寄存器地址保持，变化如下：

| 偏移 | 定义 |
|---|---|
| 00 | R4 ID=4b574604；R1 ID=4b574601 |
| 34 | 编码后的输入字节数，须与总头length一致 |
| 3c | DMA布局00100002 |
| 50 | 成功写入共享SRAM的编码字节数 |
| 60/64 | 源读取/共享入库的成功响应数 |
| 68 | 共享读回数，固定0 |
| 74 | 能力：版本2在高16位，ROW_LANES在15:8，低5位为压缩、ACK转发、队列、IRQ、debug |
| 78/7c | 解码器接受编码字节数/输出半字数 |
| 80/84/88 | 命令等待ready周期/在途等待响应周期/同拍退旧接新次数 |

18统计解码后原始23488半字，1c统计25344个结果；两者不能与编码字节计数混用。58的输出FIFO数量为13:8，挂起有效位mask=00003f1f；owner/state仅诊断。05c低5位全1表示完整入库、解码半字完成、核心完成、全部输出ACK、事务排空。

CTRL=1启动，2取消，4空闲清状态；配置仅空闲可写，启动后保持。取消/错误停止新调度，已对外VALID保持直到握手并排空，最后失效缓存。成功共享写响应才发布解码输入；报错的写不发布。DONE等待真实最终写响应及所有队列/事务排空。错误16+decoder_code表示格式错误，phase=5。总线源/入库/输出错误保持原code4/5/7及phase3/4/7；读取错误地址为保存的旧owner地址。

固件继续复用真实PLIC/CLINT配置、IRQ处理及WFI等待规则。ITCM仅固件和16B配置元数据：fff0 shift、fff4编码长度、fff8布局、fffc行数。输入/参数只通过源ICB加载，不随程序预填。构建成功不等于E203、IRQ或PPA通过。

新宏清单：64个128×16 X缓存、32个128×16 W双bank；每组最多64结果，双结果bank；32字输出FIFO、16字源FIFO、16字提交FIFO、8命令队列。原共享和TCM复用模块单列，新控制/解码/缓存全计入加速器面积。
