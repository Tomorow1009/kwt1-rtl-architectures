# T64：原总线读回版本

数值、编码和物理缓存沿用受测 N1 `9305c6948c764fed01fe86b20bb3db94170299ab`。
ID 为 `0x4b575309`，能力为 `0x000804bf`；layout 仍为 `0x00100004`，
numeric format `0x000e0c20`，SHIFT=10。原 MMIO 地址及 IRQ/WFI 语义保持。

源读、共享写、共享读、结果写都经过新增的上游公平仲裁器、原 mem_fab、
原 O4 和单入口地址路由器。原分路器参数及位宽保持。旧 O4 后仲裁位置已取消。
错误阶段新增共享读类型3，错误码6、阶段5。`0x68`返回成功共享读应答数。

每个编码32位字必须先收到对应共享写成功响应，才允许发出同地址读请求。
只有共享读成功响应的数据可进入解码FIFO；写数据及写响应不向解码器转发。
源信用3、源FIFO16、读响应FIFO16、描述符队列8、输出FIFO32均保持原容量。
读地址计数与成功写前缀绑定；所有被接受请求都必须在取消/错误后排空。

完整计时包括首源VALID的ready等待，结束于最终成功输出写响应，并验证相关事务排空。
CPU的配置/中断/结果检查也走原总线；DMA窗口不把无关CPU事务误作未排空DMA。
编码长度为B字节时，DMA事务应为 `3*(B/4)+12672`；原N1计数不适用。

本地直连仲裁器/路由器测试只证明搬运与数值，不证明原mem_fab或真实E203执行。
正式SoC额外检查每笔DMA都经过原输入、O4及目标从设备握手。
正式回归固定现有100条清单的前20条、240任务；没有100条自动运行入口。

T64计算为4×16、25个行组，末组3行；物理X缓存仍按原5行分组，共60个小宏。权重仍32个宏，内部总计23KiB。四行窗口的实际宏地址按绝对行坐标计算，携带原物理分组标签通过响应管线。两个结果槽各64项。
