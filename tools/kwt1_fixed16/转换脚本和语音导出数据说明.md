## 本次导出数据详细说明

### 1. 这100条是什么数据

本次是 **105829条真实语音中，按冻结的新格式误差选出的最差100条**。排名指标为每条语音12层FFN1完整矩阵NRMSE的最大值，降序排列；并列按语音路径排序。包含训练集83条、验证集4条、测试集13条，不含合成全零静音。

这里只用测试集检查已经冻结的配置，没有据此重新调整参数。这100条用于检查困难样本，不是随机抽样、不是按类别均衡抽样，也不是组委会最终600条评测集；不能把这100条的误差当作全体样本的平均表现。

每条语音包含 **12个完整FFN1矩阵任务**，每个任务为：

```text
X[99×64] × W[64×256] + b[256] → Y[99×256]
```

总计：100条 × 12层 = **1200个任务**；每任务25344个输出，共 **30412800个输出**。

| 数据 | 单层含义与数量 | 跨语音、跨层关系 |
|---|---|---|
| X | 当前编码模块内部FFN1的输入，99×64，共6336个数 | 不同语音、不同层通常不同 |
| W | 当前层FFN1权重，64×256，共16384个数 | 同一层跨语音固定；12层分别有自己的权重 |
| b | 当前层FFN1偏置，256个数，加到每一行 | 同一层跨语音固定；12层分别有自己的偏置 |
| Y | 当前层FFN1浮点输出参考，99×256，共25344个数 | 不同语音、不同层通常不同 |

官方模型导出的X、W、b、Y均为 **float32**。这里的“原始数据”是量化之前的模型浮点张量，不是HEX整数。包内另外保存原始WAV，方便追溯。

**12层数据都是各层FFN1的数据，不是12个完整编码器的全部中间数据。** 各层X通过完整官方模型计算后提取，已包含此前模型运算的影响。硬件可以逐层独立装载这些X/W/b；不要把第1层FFN1的Y直接当成第2层FFN1的X。Y在GELU之前，不是整个编码模块的最终输出。

**主要理解两个文件：load.hex送入硬件，result.hex用于核对最终输出。**

| 文件 | 内容和用途 | 每层数量 |
|---|---|---:|
| load.hex | X、W、b量化编码后，按RTL装载顺序排列；不是参考答案 | 23488个16位字 |
| result.hex | 定点软件模型计算出的最终signed16结果，经过舍入和饱和；与RTL最终输出逐位比较 | 25344个结果 |
| total.hex | 定点软件模型加偏置后的signed41总和，位于输出舍入之前；用于核对乘加结果 | 25344个总和 |
| saturated.hex | 每个最终输出是否触发饱和的参考标志 | 25344个标志 |
| expected.npz | total/result/saturated的NumPy数组版本，供软件核查 | 一套完整输出数组 |
| layout.json | 层号、装载字数、数值格式、shift和相关文件哈希 | 一份 |
| hex_check.json | HEX独立回读核查、裁剪和饱和计数、浮点误差记录 | 一份 |

load.hex的23488个16位字包括：X的6336个字，以及32组权重/偏置。每组有512个权重字和8个偏置，每个40位偏置占3个16位字，因此总数为6336 + 32×(512+8×3) = 23488。它不是把完整X、完整W、完整b随意依次拼接；必须保持转换器生成的顺序。

```text
load.hex → 按协议装载SRAM/加速器 → RTL计算实际输出
                                      ↓
                              与result.hex逐位比较
```

**参考结果不参与DUT运算。** 当前testbench还会读取total.hex和saturated.hex，所以虽然load/result最重要，使用现有testbench时应保留四种HEX，不能只上传两个文件。

### 4. 三种“结果”不要混淆

| 结果 | 来源 | 比较目的 |
|---|---|---|
| 原始NPZ中的浮点Y | 官方浮点模型 | 衡量我们定点方案的量化误差、计算NRMSE |
| result.hex | 与RTL协议一致的定点软件模型 | 检查RTL最终输出是否逐位一致 |
| total.hex | 定点软件模型舍入前的整数总和 | 定位乘法、累加、偏置或输出转换的问题 |

result.hex先按16位有符号补码解释，再除以4096得到实际数值。total.hex按41位有符号补码解释，再除以2^28。不能把十六进制文本直接当成无符号实数，也不能把total当作最终输出结果。

结果参考按矩阵行优先保存；比较RTL输出时使用行列坐标：**参考索引 = row×256 + column**，row为0～98，column为0～255。RTL实际发出结果的顺序与参考文件行顺序不同，不要按到达顺序逐行比较。

## 转换脚本使用方法

### 1. 脚本负责哪一步

本脚本把“官方模型已经提取出来的浮点矩阵”量化、排列并编码为HEX，同时生成定点参考结果和校验记录。它不直接读取WAV运行官方模型，也不负责向服务器或SRAM写入数据。

脚本只依赖Python 3.6+和NumPy，不需要TensorFlow。格式固定为X signed16/F12、W signed16/F16、b signed40/F28、total signed41/F28、Y signed16/F12；SHIFT=16，最近舍入、半值远离零，再饱和。

### 2. 命令中每个参数是什么意思

~~~sh
python convert_kwt1_fixed16.py --sample float_tensors.npz --weights shared_weights.npz --out NEW_HEX_DIRECTORY
~~~

| 命令部分 | 含义 | 应填写的内容 |
|---|---|---|
| python | 调用Python解释器 | 已安装且能导入NumPy的Python，也可以用python.exe的完整路径 |
| convert_kwt1_fixed16.py | 执行转换脚本 | 本文件夹中的脚本文件路径 |
| --sample | 指定某一条语音的浮点数据文件 | 后面填写该条语音的float_tensors.npz路径，不是WAV路径，也不是整个目录 |
| --weights | 指定浮点权重和偏置文件 | 后面填写shared_weights.npz路径；同一模型的100条语音共用这一份文件 |
| --out | 指定HEX输出目录 | 后面填写一个尚不存在的新目录，脚本会创建它并生成12层数据 |

--sample、--weights、--out是固定的参数名称，不能随意改写。它们后面的文件名和目录名是路径，可以替换。NEW_HEX_DIRECTORY只是示例占位名，不是特殊参数。

**当前命令一次处理“一条语音的完整12层”，不是一次处理100条。** 转换下一条时，更换--sample和--out，保留同一个--weights。

### 3. NPZ文件内部需要有什么

NPZ是NumPy数组容器，可以按名称保存多个数组。不能把任意文件改为.npz后缀就直接使用。数组名称区分大小写：X、Y、W大写，b小写。

| 文件 | 数组名 | 当前要求的形状 | 含义 |
|---|---|---|---|
| --sample指定的文件 | X，必需 | (12,99,64) | 一条语音在12个编码模块内部，各自FFN1的完整浮点输入 |
| 同上 | Y，可选 | (12,99,256) | 官方模型12层FFN1的浮点输出参考，位于GELU之前 |
| --weights指定的文件 | W，必需 | (12,64,256) | 12层各自的FFN1权重 |
| 同上 | b，必需 | (12,256) | 12层各自的FFN1偏置 |

第一维12表示12层，不是12条语音；索引0对应第1层，索引11对应第12层。X/W/b必须按相同层顺序匹配。同一层的W/b跨语音固定，各层之间的W/b不同。

本包原始数组为float32；输入数值必须有限，不能含NaN或无穷大。X必须是FFN1入口数据，不能用原始语音、MFCC或编码器入口张量代替。

没有Y也能生成HEX和定点参考结果，并检查HEX回读一致性；但不能据此报告相对官方浮点Y的NRMSE。提供Y时会额外计算该误差。原始包中的logits是模型分类输出，本脚本不使用它。

### 5. 官方只给某条语音某一层的原始数据，能不能转换

**计算上可以。一个FFN1任务不需要同时具备12层数据。但当前交付脚本的命令行只支持完整12层NPZ，不能直接接收单层数组。** 现有代码会检查(12,99,64)等形状，直接传单层数据会报错。

单层完整FFN1转换需要：

| 数据 | 单层形状 | 要求 |
|---|---|---|
| X | (99,64) | 必需；必须是这一层FFN1的完整浮点输入 |
| W | (64,256) | 必需；使用这一层的官方权重 |
| b | (256,) | 必需；使用这一层的官方偏置 |
| Y | (99,256) | 可选；官方浮点输出参考，用于计算NRMSE |
| 层号、排列约定 | 第1～12层之一 | 需要明确，以便正确匹配权重、偏置和矩阵坐标 |

如果官方提供完整单层X/W/b，就可以独立计算Y=X×W+b，不需要我们在硬件中先运行前面的编码器。前提是X已经是该层的FFN1入口。

| 官方提供的数据 | 能否直接用当前命令转换 | 需要做什么 |
|---|---|---|
| 当前规定格式的完整12层NPZ | 可以 | 按上面的命令执行 |
| 完整单层X/W/b | 当前命令不支持；计算本身支持 | 增加单层入口、形状检查和层号记录，复用现有整数计算核心 |
| 只有完整单层X | 不可以 | 先取得对应层W/b，再使用适配后的单层入口 |
| 原始WAV、MFCC或编码器入口 | 不可以 | 先用指定官方模型提取目标层FFN1输入 |
| 一个点积或仅Y[0,0]相关数据 | 不能生成完整矩阵任务 | 只能用于点积验证，需要补充真实的完整矩阵 |
| CSV、TXT或其他字段/排列的文件 | 不保证可以 | 先适配文件读取、数组名称、形状和排列 |

**单层命令行功能当前尚未加入，本说明没有修改转换脚本。** 后续若官方采用单层输入，应适配工具入口，不应把一层复制成12层、或补零来绕过检查。

还要确认权重方向：某些工具导出W为(256,64)，本协议要求(64,256)。应按模型定义确认是否需要转置，不能仅凭元素总数相同就直接使用。

“12层打包输入”是当前工具的接口选择，不是赛题规定每次必须同时提供12层。

### 6. HEX怎样与RTL配合

| 文件 | 用途 |
|---|---|
| load.hex | DUT输入，包含X/W/b；每层23488个16位装载字 |
| result.hex | 最终signed16输出参考，每层25344个值，解码除以4096 |
| total.hex | 舍入前signed41总和参考，解码除以2^28 |
| saturated.hex | 饱和标志参考 |

装载数据按当前硬件分组协议排列。输出参考按矩阵行优先保存，RTL实际输出流必须按行列坐标匹配，不能直接reshape。参考文件只供检查，不参与DUT运算。

仿真运行时保留原数据路径参数，追加+SHIFT=16；连续第二任务也采用新格式时追加+SECOND_SHIFT=16。E203实际驱动通过集成配置接口设置shift=16。

脚本会独立回读HEX并重新计算核查，记录裁剪和饱和次数。软件HEX检查通过不代表RTL/SoC验收通过。新HEX与新SHIFT配置必须配套，不能和旧Q12数据混用。
