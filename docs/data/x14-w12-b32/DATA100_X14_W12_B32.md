## 数值与装载协议

12层统一使用：X signed14/F10、W signed12/F12、乘积signed26/F22、累加器signed32/F22、b signed32/F22、total signed33/F22、result signed16/F12；SHIFT=10，半值远离零舍入、signed16饱和。

仍为group8布局，外部ICB32位、SRAM字16位。X14/W12符号扩展到16位。b32符号扩展到40位再以三个16位字承载，高字只含高8位，其上8位填0；b=-1为ffff、ffff、00ff。计算内部只使用signed32偏置。

| 每层文件 | 行数 | 用途 |
|---|---:|---|
| load.hex | 23488 | 16位装载字：6336个X字，再32组，每组512个W字和24个b字 |
| result.hex | 25344 | signed16最终参考，每行4字符，解码除4096 |
| total.hex | 25344 | signed33总和参考，每行9字符，解码除2^22 |
| saturated.hex | 25344 | 每个输出的饱和标志，0或1 |
| layout.json | — | 格式、层号及4个HEX的大小/哈希 |
| hex_check.json | — | 回读重算、裁剪/饱和及浮点误差 |

total的负数按33位补码读取，例如-1为1ffffffff。testbench必须按signed[32:0]读取，或读取后显式符号扩展；不能按旧41位直接读取。参考按row→column排列，RTL输出须按row*256+column检查，不直接reshape输出流。参考文件不进入DUT运算。

## 如何复现100条

脚本文件和脚本说明不变：`convert_kwt1_x14_w12_b32.py --archive ...` 的既有入口仍只生成前30条。本次通过同脚本已有API循环全部100条，不能把该命令单独运行结果误报为100条。

下面在脚本所在目录运行的Python代码可重建全部样本目录及逐层检查记录；OUT选不存在的新目录。不会生成本次批处理的根manifest/总哈希清单；重建后应与本包SHA256_FILES.json核对全部4800个HEX，才能确认等价。

```python
import zipfile
from pathlib import Path
import convert_kwt1_x14_w12_b32 as c

archive = Path(r"D:\转换脚本\KWT1_WORST100_20261109\KWT1_WORST100_ORIGINAL_FLOAT.zip")
out = Path(r"D:\转换脚本\hex_short\hex100_reproduced")
out.mkdir(exist_ok=False)
with zipfile.ZipFile(str(archive)) as z:
    root = "KWT1_WORST100_ORIGINAL_FLOAT/"
    weights = c.arrays(z.read(root + "shared_weights.npz"), weights=True)
    for n in range(1, 101):
        name = "sample_%03d" % n
        data = z.read(root + name + "/float_tensors.npz")
        c.convert_sample(data, weights, out / name)
        print(name, "12 layers checked")
```

单层重新检查：`python convert_kwt1_x14_w12_b32.py --check "<hex目录>/sample_001/layer_01"`。转换不需要TensorFlow，只需要Python和NumPy。
