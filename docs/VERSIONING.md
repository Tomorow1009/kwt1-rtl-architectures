# 架构与版本管理约定

## 目录

```text
architectures/
  arch01_serial_mac/
    v1.0.0/          # 本次已验证基线
  arch02_matrix/    # 实现时再建立版本目录
  arch03_soc/       # 实现时再建立版本目录
docs/
templates/
```

每个版本包含 RTL、testbench、仿真脚本、输入样例、架构说明、验证结果。沿用现有版本代码时，注明基于哪一版本及具体变更。

- 功能开发创建 `feature/<主题>` 分支，修复用 `fix/<主题>`；提交 PR 合并至 main。
- main 保存可交接的代码；每次 PR 同时更新相关文档和测试结果。
- 不覆盖旧版本目录：需要交付新的阶段快照时建立新版本目录，并更新根 README 索引。
- major：接口或数值协议不兼容；minor：新增兼容功能；patch：修复和说明完善。
- Git 提交记录保留开发过程；版本目录保留交接快照。稳定后可由维护者创建 `arch01-v1.0.0` 一类 tag；本次只建立版本目录，没有声称已创建 tag。
- 仿真成功与综合/时序成功分别记录，不能互相代替。

每次交接应明确：架构版本、源提交、数值格式、接口、数据布局、运行命令、工具版本、通过/未通过项、已知问题及下一步。
